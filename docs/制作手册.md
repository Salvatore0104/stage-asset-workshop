# 本地素材工坊｜通用制作手册

> 本文件解释底层制作和验收原则。本 GitHub 版本以 `03_资产与需求/show.json` 为唯一输入规格，`05_素材工坊/project.config.json` 为自动生成的底层配置；目录与执行流程以 [目录结构](目录结构.md)、[配置说明](配置说明.md) 和 [INSTALL.md](../INSTALL.md) 为准。生成使用 Wowidea CLI 的默认直接接口，不要加 `--direct`。下文 Canvas 2D 指浏览器绘图 API，用来预览舞台，不是要去操作的外部无限画布。

版本：1.0 · 2026-10-17  
适用对象：接手新专案的 Codex／制作人员  
交付目标：可离线开启、分段预览、依 BPM 动画、分层输出透明 PNG 序列，供 After Effects 合成的本地 HTML 素材工坊。

> 这份手册参考《快乐崇拜》素材工坊 V4 的工作方式，重新抽出通用规则。**不继承该专案的解析度、舞台形状、素材、段落、PGM 需求、字型或 API 服务。**每个新专案都从自己的规格建立。
>
> 附带程式为可执行的精简起点，含两个示范段落。它不是 V4 的完整复制，也不包含该专案的 PSD、角色、影片或字型。完整制作仍需按下列流程还原新设计稿、拆层及编写动画。

## 1. 给接手 Codex 的工作要求

1. 使用中文沟通；先读本手册、启动指令及使用者提供的专案资料。
2. 在新版本目录工作，保留原稿和旧版。不要覆盖使用者提供的原始 PSD、遮罩和素材。
3. 先查阅档案，能从素材中读取的资讯自行确认。只有解析度、遮罩语意、PGM 需求等会改变交付结果、又无法确认的资讯才需要询问。
4. 先完成静态对位，再做动画，再验证正式解析度的输出。不要用漂亮的动效掩盖错误排版。
5. 专案规格集中于 `project.config.json`，不要把尺寸、帧率、主屏座标或遮罩形状散落在程式里。
6. 若本次只收到手册，先建立规格表及功能样机；缺失的正式规格标记为「待确认」。不要宣称示范尺寸是舞台正式尺寸。
7. 日常预览可降解析度；正式输出必须回到指定尺寸。预览尺寸不能成为制作座标系。
8. 素材生成服务可选。无需生成就直接利用原稿和程式动画；需要时使用当前环境可用工具，不写死供应商、模型、网址、凭证或计费参数。
9. 调整、建置、验证和使用方法都要留在交付包；成品整个资料夹能搬到另一台电脑使用。

## 2. 新专案规格表

开工先建立 `PROJECT_BRIEF.md`，填写下表。这是正式制作的依据，示范设定只用来验证功能。

| 项目 | 必须记录的内容 |
|---|---|
| 专案名称／代码 | 显示名称；档名用英数、底线或短横线 |
| 舞台总画布 | W × H，以像素为单位；确认是整台映射图还是单屏画面 |
| 舞台遮罩 | 档名、尺寸、白／黑／透明的意义、是否反相、是否含灰阶羽化 |
| 屏幕区域 | 每块屏幕的位置、大小、形状、主屏／侧屏／返送等名称 |
| PGM | 是否需要现场画面洞口；洞口形状及位置；是否需要独立 matte |
| 设计资料 | PSD／PNG／AI／影片／参考图／字型／音乐；指定采用版本 |
| 段落表 | ID、名称、秒数或拍数、循环或单次、前后段转场 |
| 时间基准 | BPM、FPS、起拍偏移、是否变速／需要音讯时间码 |
| 输出 | 全画布或分屏切片、解析度、透明通道、PNG 序列、静态素材 |
| 合成 | AE 专案 FPS、混合模式、图层堆叠、色彩与 Alpha 解读 |
| 尺寸限制 | 可用记忆体、长段帧数、预期交付容量 |

**不能猜的关键条件：**正式画布、遮罩白黑含义、是否要 PGM、最终 FPS。若缺少这些条件，可继续整理素材与开发 UI，但正式定位／输出应标示为未验收。

## 3. 最终应有的工坊体验

参考 V4 的重点是「可操作的素材工作台」，不只是播放影片。

- 段落选择、播放／暂停、时间轴逐帧定位、帧号／时间显示。
- BPM 可调；以拍数定义的段落随 BPM 改变时长；秒数段落维持固定秒数。
- 舞台遮罩只控制预览遮挡的程度；至少可关闭、半透明、完全遮住非成像区。
- 预览图层可独立开关；有清楚的图层说明与堆叠顺序。
- 指定图层、全部制作图层、合成参考、独立舞台遮罩；启用 PGM 才提供 PGM matte。
- PNG 输出可选尺寸与帧范围，逐帧写入资料夹，显示进度、取消及错误。
- 静态图层只输出一张；动态层输出完整序列；每层保留相同全画布尺寸。
- 即时 WebM 供快速预览；正式逐帧交付以 PNG 序列为准。
- 如需歌词、计分、章节标题、年代选择等，做成该专案的可编辑参数，不硬套旧节目内容。

附带范本已具备上述核心操作；歌词编辑、音讯播放、变速节拍表、分屏切片、影片拆帧及 AI 制作需按专案扩充。

## 4. 目录与可携性

建议新专案结构：

```text
MyProject/

├─ project.config.json           # 唯一规格来源
├─ input/                        # 使用者原始资料，保留原件
│  ├─ psd/
│  ├─ masks/
│  ├─ audio/
│  └─ references/
├─ assets/                       # 已确认可用的拆层图／动画帧
├─ psd_extract/                  # PSD 图层与 manifest
├─ src/
│  ├─ index.html                 # 工坊介面
│  ├─ engine.js                  # 时间／图层／遮罩／渲染
│  ├─ scenes.js                  # 新专案的分段动画
│  └─ app.js                     # 操作与输出
├─ tools/
│  ├─ build.py
│  ├─ extract_psd.py
│  └─ check_export.py
├─ dist/                         # 每次建置建立新目录
├─ exports/                      # 正式透明素材
├─ previews/                     # 小样、对位图与影片

```

附带建置器把设定和素材转为本地 HTML + JS 分包，不在执行时 `fetch()` 本地 JSON，也不依赖 CDN。请整个成品资料夹复制；只传 HTML 可能遗失素材。分包约以 8 MiB base64 内容为目标；单一素材超过此值时会独占较大的分包，不是硬上限。分包不代表素材不占记忆体。

## 5. 设定方式：不同尺寸只改规格与排版

`project.config.json` 的主要栏位如下；以同包实际 JSON 为可执行范例。

| 栏位 | 意义 |
|---|---|
| `stage.width / height` | 正式全画布像素尺寸 |
| `fps` | 正式帧率；目前范本只接受正整数 |
| `bpm` | 初始 BPM；在 UI 改变后会记录在输出 manifest |
| `previewMaxWidth` | 预览上限，与正式输出分离 |
| `imageSmoothing` | 平滑缩放；像素风格可设 `false` |
| `clipExportToStage` | 输出是否依舞台遮罩裁成透明；预设 `false`，介面可改 |
| `stageMask` | 舞台成像区，支援几何形状或全尺寸 PNG |
| `pgm.enabled / mask` | 是否建立 PGM matte 以及洞口范围 |
| `assets` | 图片路径及全舞台座标；路径相对于此 JSON |
| `parts` | 段落、时长、图层、静态／动态、PGM 挖洞等 |

**不要把「通用」理解为只缩放旧成品。**换了舞台形状，主体可能需要移位、拆到不同屏幕、重新安排留白与遮挡。设定确保规格一致，排版仍要针对新舞台设计。

29.97／59.94 等需求不能直接近似成 30／60。若使用这类工程，先把时间系统扩充为有理数 FPS（例如 30000/1001），同步修改帧数计算、显示、记录及验证；目前范本不支援。

## 6. 遮罩：先定义语意，再用图

### 6.1 三种概念必须分清

| 种类 | 用途 | 是否写进正式内容 |
|---|---|---|
| 预览遮挡 | 帮人看出舞台哪些区域不成像；遮罩外叠黑 | 不写进 PNG 内容 |
| `stage_mask` | 白色＋透明的独立舞台覆盖率；可供后期裁切 | 独立一层；是否裁内容另选 |
| `pgm_matte` | 白色代表现场影像可放入的洞口范围 | 依专案启用，与舞台遮罩不同 |

非成像区「黑色」是舞台描述，不代表所有透明素材都要填黑。预览黑色遮挡、输出裁切、黑底内容是不同选项。

### 6.2 几何遮罩

多块矩形、不规则多边形可使用 `geometry`，所有座标都是舞台像素，原点在左上，X 向右、Y 向下。

```json
{
  "type": "geometry",
  "shapes": [
    {"type": "rect", "x": 0, "y": 100, "w": 400, "h": 600},
    {"type": "polygon", "points": [[500,100],[1400,100],[1600,700],[500,700]]}
  ]
}
```

这段仅示意资料格式，必须让所有点位落在实际舞台内。多个形状取联集；多边形顶点使用一致方向、避免自交。带洞形状、曲线、重叠方向不明的形状或需精准羽化时，优先提供完整舞台尺寸的 PNG 遮罩。

### 6.3 PNG 遮罩

```json
{
  "type": "image",
  "file": "input/masks/stage_mask.png",
  "channel": "luminance",
  "invert": false
}
```

- 黑底白区 PNG：用 `luminance`，白色保留，黑色去除，灰色保留部分覆盖率。
- 已带透明区的 PNG：可用 `alpha`，不透明处保留，透明处去除；图片的 RGB 颜色不影响结果。
- 黑底白区且整张不透明的图若误用 `alpha`，会整张保留。必须先检查像素，不能只看副档名。
- 范本 `luminance` 的覆盖率为亮度 × 原图 Alpha；`invert` 反转最后覆盖率。
- PNG 必须与正式画布完全同尺寸。尺寸不符先追查来源，**不可默默拉伸遮罩**。
- JPG 压缩会污染边界，PDF／SVG／PSD 也不能直接当范本遮罩；先以指定像素尺寸转成 PNG 并检查。

范本载入时会把遮罩正规化成「白色 RGB＋覆盖率 Alpha」，再用 `destination-in/out`。**Canvas 的这两种运算看的是 Alpha，不是黑白亮度。**直接拿不透明黑白 PNG 做 Alpha 裁切会失效。

### 6.4 PGM 不是每个专案都有

- `pgm.enabled=false`：不产生 PGM matte，也不进行洞口挖空。
- `true`：启用 `pgm_matte`；需要挖洞的内容层加 `cutPgm:true`。
- matte 是对应洞口的白色形状。正式内容层在相同位置真的透明，不能只画一块绿色假装洞口。
- 每层独立挖洞后再合成；不能在已合好的总画面上随意挖洞，否则可能擦掉本来应位于洞口后方的内容。
- 若背景、装饰或特效盖住 PGM，需要逐层判断是否挖洞；不是只挖框体就完成。
- 洞口内保留的前景玻璃光／光晕应单独成层，写明放在 PGM 上方及 AE 混合模式。
- PGM 需要动画遮罩时，目前范本的全段静态 matte 不足；须改成逐帧绘制并移除静态标记。

## 7. 素材拆解与静态还原

### 7.1 先读 PSD，不要凭缩图重画

1. 记录 PSD 原始尺寸、版本、图层树、可见性、图层范围 `bbox`、不透明度、混合模式。
2. 建立参考合成图；最好保留设计师在 Photoshop 汇出的正式参考。
3. 输出所需图层，保留名称与路径；索引只作辅助，不要跨 PSD 版本沿用旧图层序号。
4. 把会被拆成动画的主体独立整理：背景、框体、萤幕内容、标题、角色、前景特效等。
5. 先在正确舞台位置合成静态画面，逐区与设计稿核对，再开始动效。

附带 `extract_psd.py` 输出 raw layer PNG、manifest 及参考合成。**raw PNG 不等于 Photoshop 最终外观**：群组透明度、调整层、图层样式、剪裁遮色片、智慧物件、字型及混合可能造成差异。若合成不一致，改由 Photoshop 汇出关键图层／群组，不要把近似结果当成已还原。

### 7.2 三个座标系

必须区分：PSD 原稿座标 → 舞台正式座标 → 预览／输出像素。

以等比缩放及平移为例：

```text
舞台 x = 目标锚点 x + (PSD x - 原稿锚点 x) × scale
舞台 y = 目标锚点 y + (PSD y - 原稿锚点 y) × scale
舞台宽高 = 原稿宽高 × scale
```

素材若先裁掉透明边，必须把裁切左上偏移加回 PSD 的 `bbox`，再做映射。不能裁完后把所有图层都丢到 0,0。

- `contain`：完整放进目标区，可能留白。
- `cover`：填满目标区，会裁边；主体不能被意外切掉。
- 拉伸：只有明确允许时才非等比缩放。
- 左右屏、主屏及特殊屏可使用不同映射；各区的锚点、比例和裁切理由都要记录。
- 参考原稿与新舞台比例不同时，不要一律整体缩放，也不要以预览 canvas 的尺寸安排正式素材。

### 7.3 素材表与绘制

把透明 PNG／WebP 放入 `assets/`，在设定加入：

```json
"assets": {
  "hero": {"file": "assets/hero.png", "x": 400, "y": 120, "w": 800, "h": 400, "opacity": 1}
}
```

然后在 `scenes.js` 的指定层绘制：

```js
if (layer === 'art') {
  api.image(g, 'hero', {dy: -20 * Math.sin(s.phase * Math.PI * 2)});
}
```

此处数值只是示意。静态图依正确位置输出；动态变形以素材基准座标为起点。像素图可关闭平滑并尽量使用整数倍缩放；标题和字型不能靠低解析度放大冒充高清。

## 8. 分段、分层与动画

### 8.1 每段建立制作卡

| 项目 | 例子（需改成本专案内容） |
|---|---|
| ID／名称 | `S01`／开场 |
| 时长 | 固定 6 秒，或 16 拍；两者选一 |
| 类型 | 单次入场、循环、一次结尾 |
| 图层顺序 | background → art → frame → fx |
| 动画事件 | 0–2 拍入场、2–12 拍主循环、12–16 拍转场 |
| 透明及遮罩 | 哪些层留洞、何处裁切、是否有 PGM |
| 接续条件 | 与前段／后段在颜色、位置、速度上的衔接 |
| 可编辑参数 | 文案、歌词、颜色、计分等 |

图层阵列顺序即由下到上。`static:true` 仅用于全段每一帧都完全相同的层；只要有呼吸、抖动、颜色变化、文字更新就不是静态。

### 8.2 增加段落需要两处

先在设定加入段落：

```json
{
  "id": "S01",
  "name": "开场",
  "duration": {"unit": "beats", "value": 16},
  "loop": true,
  "layers": [
    {"id": "background", "name": "背景", "static": true},
    {"id": "art", "name": "主视觉"}
  ]
}
```

再在 `scenes.js` 注册相同 ID：

```js
window.WORKSHOP_SCENES.S01 = (g, s, layer, api) => {
  if (layer === 'background') {
    g.fillStyle = '#101020'; g.fillRect(0, 0, s.width, s.height);
  }
  if (layer === 'art') api.image(g, 'hero', {scale: 1 + .025 * Math.sin(s.phase * Math.PI * 2)});
};
```

只有设定、没有同 ID 绘图函式时，初始化会报错。内建示范场景只注册 `intro`、`loop`。

### 8.3 动画必须能直接计算任意帧

正式渲染采 `render(frameIndex, config)`，不靠前一帧累积状态。拖时间轴、倒序查看、单独汇出其中 10 帧，画面都要一致。

- `t = frameIndex / fps`；`beat = t × BPM / 60`。
- 以拍数定义：`durationSeconds = beats × 60 / BPM`。
- 以秒定义：变 BPM 不改段落秒数；其中随拍元素仍可随 BPM 动。
- 粒子使用固定 seed／依粒子 ID 的确定参数，再以时间计算位置。不要在每次 draw 时 `Math.random()`；也不要让速度依赖萤幕刷新频率。
- 范本统一 `N = max(1, round(durationSeconds × fps))`，实际段长为 `N/fps`。帧数与理想时长不整除时，把实际值写在介面与 manifest，避免各工具各自取整。
- 起拍偏移、音讯同步、变 BPM 乐曲不在精简范本内；需要时先建立节拍／事件表，不能假设固定 BPM 能解决所有歌曲。

### 8.4 循环不要重复端点

取样为 `f = 0 ... N-1`，通常使用 `phase = f/N`。概念上在 `f=N` 回到 `f=0`；**不另外输出 `f=N`**。

最后一张与第一张不必像素完全相同；要检查的是最后一张到第一张的运动是否连续。硬把两张设成一样可能造成短暂停顿。对 AI 影片也一样：检查实际素材，确认存在重复尾帧才移除，不能无条件删最后一张。

循环粒子要处理跨周期存活、位置回接、透明度及速度。单次入场／出场可以另外拆成段落；不要让循环中段突然重新入场。

## 9. 可选的 AI 图／影片制作

原设计稿能完成的内容优先使用原素材和程序动画。若要生成角色姿势、金属扫光、玻璃／3D 小物、循环片段：

1. 为每个任务保留原图、目的、提示词、模型与参数、结果档及采用状态。
2. 人物强调身份、服装、比例、站位、脚底基准及画风一致，只改指定动作；逐帧检查手脚、脸和文字。
3. 多帧素材要共用同一 bounding box 和锚点，先对齐再播放，避免主体跳位置。
4. 影片先按交付 FPS 拆帧，验证循环与时长，再打包；不要在正式渲染时即时寻址播放压缩影片来假装精准逐帧。
5. 可使用透明输出；若采绿幕／蓝幕，先确认不会误删角色或发光中的同色成分，检查边缘、溢色和半透明处。
6. 生成人工智慧内容不保证精准文字、无缝循环或与 PSD 同尺寸，必须检查和修正。
7. 生成结果做快取，已采用的档案重建时直接重用。重建工坊不应意外重跑付费生成。
8. 凭证不放在 HTML、JS、JSON 或交付包；使用受管登入或环境变数，不将私人 token 写进日志。

此套件未包含任何服务呼叫，也没有旧专案 API 参数依赖。

## 10. 输出与 AE 使用规则

### 10.1 PNG 序列

1. 选段落、图层、输出宽度、起止帧（含结束帧）和是否依舞台裁切。
2. 确认画布比例与正式规格一致；高度由舞台比例计算，正式交付通常使用原尺寸。
3. 选择输出根资料夹；范本每次自建一个唯一子资料夹，避免短段重新汇出后混入旧版尾帧。
4. 一层一个子资料夹；动态 PNG 连续编号；静态层只有一张，合成时延长持续时间。
5. 读取 `export_manifest.json`：解析度、FPS、BPM、帧范围、图层、混合模式、裁切状态、完成状态。
6. 取消或写入失败保留已完成 PNG，manifest 保持未完成，不能把局部输出交付成完整序列。此范本不提供自动续传，需重新输出或另行实作续传验证。

「全部制作图层」逐层输出所有制作层，包含预览关闭的版本／特效；遮罩另外成层。合成参考使用目前勾选的图层。不要把这两种操作混为一谈。

若环境不能选资料夹，先使用单张下载检查；正式序列改用支援目录选取的环境或由 Codex 启动 localhost。不要自动触发数千次浏览器下载。若需跨浏览器正式批次交付，可另加离线逐帧渲染工具。

### 10.2 透明与混合模式

- PNG 必须保留 RGBA；透明区不得烘焙棋盘格、预览遮挡或不需要的黑底。
- PNG 的 Alpha 按 Straight／未预乘理解；AE 中检查素材解读，半透明边缘不应有黑／白晕。
- `source-over` 对应一般正常叠放；`lighter` 常用于相加效果；其他混合模式逐项在 AE 验证。
- 单层 PNG 不会把「相加」之类的堆叠设定永久存进档案，必须提供图层说明／manifest，让 AE 重设。
- Canvas 合成与 AE 的色彩管理、线性工作空间、混合运算不保证像素一致。正式交付要以目标 AE 工程核对。

### 10.3 AE 汇入

1. 建立正式 W×H、指定 FPS 的合成。
2. 动态层选第一张并以 PNG 序列汇入；确认解读 FPS，而不是只看合成 FPS。
3. 静态层以单张图片汇入，延长到段落结束。
4. 所有全画布图层在合成正中心、100% 比例叠放；不要对每层自动裁边后再猜位置。
5. 依图层顺序与混合模式重建；PGM matte 作 Alpha／Luma 轨道遮罩时先确认洞口语意。
6. `stage_mask` 如需套用整体，可放在预合成外统一裁切；若已在工坊裁切，不要再以反向遮罩重复处理。
7. 输出范围从非零帧开始时，档案仍使用原始帧号；依 manifest 的 `sourceFrameStart` 放到正确时刻。

### 10.4 WebM 的用途

范本录制目前预览画布，包含图层勾选与预览遮罩；以黑色背景录制。它走即时录制，画面太重、分页在背景或设备负载高时可能掉帧，不能取代正式透明 PNG 序列。范本不录音、不承诺 Alpha 影片输出。

## 11. 建置顺序与效能

建议流程：原稿整理 → PSD／向量输出 → 对位与素材表 → 必要的 AI／影片后处理 → 段落绘图 → 建置 → 正式解析度抽检 → 透明序列验证。

附带建置器只打包已存在的素材，不擅自重生图、不重算 PSD，不会清掉后处理条目。若新增素材处理流水线，应从来源 manifest 决定依赖，避免全量重建覆盖 AI 动画或手动修正。

全尺寸 RGBA 单张原始记忆体约为 `W × H × 4 bytes`。实际还有预览、图层暂存、遮罩、编码和素材解码；同时建立多个大画布可能超过设备能力。不要把「逐张写入」宣称为不占记忆体。

- PNG 逐张渲染／编码／写入，不能先把全段所有 Blob 放进阵列。
- 降解析度预览；静态层只输出一张；素材保留足够但不过度的像素。
- 精简范本将图片分包后全部解码；大量影片帧需另做依段载入／快取释放，否则记忆体仍可能很高。
- 超宽舞台先测一张正式图，确认画布与 PNG 编码可用，再跑完整段。浏览器限制随装置而异，不设想当然的最大值。
- 超出能力时，改为分层／分段离线渲染或安全切片后合并；最终仍验证回原解析度，不能悄悄缩小交付。

## 12. 验收流程

每次正式交付建立 `QA.md`，写出真实跑过的结果。建置成功不等于所有动画与输出已验收。

| 检查 | 通过条件 |
|---|---|
| 规格 | 舞台、FPS、BPM、时长与本专案规格一致 |
| 可携 | 成品整夹换路径后能开；正式素材不依赖作者电脑绝对路径／CDN |
| 缺素材 | 遗失素材立即报错，不安静跳过而出空图 |
| 静态还原 | 主体、色彩、字型、描边、混合与参考对得上 |
| 遮罩 | 白黑／透明／反相正确；四角、边界、狭窄侧屏与曲线逐区检查 |
| PGM | 需求有无一致；相关内容层洞口真的透明，matte 同位置同尺寸 |
| 时间 | 改 BPM 后拍数段改时长、固定秒数段不改秒数；帧界正确 |
| 动画 | 直接跳到任意帧、重复渲染、顺序改变后结果一致 |
| 循环 | 播放至少三轮，尾→首连续；无多输出端点和重复停顿 |
| 分层 | 单层输出没有其他层污染；混合模式与 AE 堆叠有说明 |
| 正式抽帧 | 每段首、中、尾、转场峰值／主体落地等重要帧，在原尺寸核对 |
| 序列 | 档名连续、帧数正确、尺寸一致、Alpha 存在、manifest 完成 |
| 故障 | 取消、错误输入、资料夹取消、缺图、遮罩尺寸错误不造成误交付 |
| AE | 实际汇入抽样序列，位置、速度、透明边缘与混合模式符合需求 |

可使用 `tools/check_export.py` 自动检查序列尺寸、Alpha 通道存在、命名、连续性和完成状态。它不会判断美术、洞口位置或每个透明像素是否正确，仍需抽图与 AE 检查。

范本提供 `window.workshopAPI` 供浏览器测试。`ready` 为真后，可指定段落、帧、图层、宽度、BPM 与裁切选项得到 Canvas；这个 API 不改变预览选段。

```js
const canvas = window.workshopAPI.render({
  partId: 'loop', frame: 25, layerIds: ['art'],
  width: window.workshopAPI.config.stage.width, bpm: 120, clip: false
});
```

## 14. 与原 V4 的对应与取舍

本手册保留 V4 的关键工作方式：整台舞台座标、原稿拆层、可调 BPM、分段动效、图层开关、舞台遮罩预览、独立 PGM matte、透明序列、静态单张及预览影片。

以下旧条件全部改为专案设定：7800×1900、阶梯侧屏、25fps、年代段落、固定秒数、歌词计分、小电视／手柄，以及特定图层索引。旧初始化说明中「没有 PGM」的节目限定与固定服务资讯不适用于新专案。旧介面文字和实际程式若有时长差异，先核对新规格与计算结果，不能照抄过期说明。

若希望新专案达到 V4 的美术丰富度，接手 Codex 必须依新设计完成素材拆解、场景编排、遮挡关系、节拍事件、角色／特效动画与转场；本范本提供基础功能与验收规则，无法自动把不同 PSD 变成完整美术成品。
