# 本地与 GitHub Pages 部署

`build` 产生独立静态站点，在 `04_输出交付/<版本>/web`。本地双击 `index.html` 可预览；若浏览器不支持选择 PNG 输出目录，可用 localhost 服务。

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory "04_输出交付/版本/web"
```

发布需 `git`、`gh` 和当前账号对目标仓库的权限。`deploy --repo owner/name` 表示明确要求创建或更新这个节目站点；新仓库为公开，已有仓库仅使用工具管理的 `gh-pages` 分支，源码分支不改动。

工具复制构建产物到临时 checkout，以普通提交推送 gh-pages，调用 Pages API 配置分支发布，不强推、不依赖 Actions workflow 写入权限。已有 gh-pages 如果不是本工具管理的站点，停止覆盖。

公开内容包括采用的背景图、网页程序和运行时节目配置。不会发布节目整个源文件夹、原始 PSD、任务记录、CLI 认证或未设置嵌入的音频。若正式素材不适合公开，请只本地构建或选择有访问控制的其他托管方案。

推送后 GitHub 需要完成 Pages 构建：

```bash
gh api repos/owner/name/pages
gh api repos/owner/name/pages/builds/latest
```

检查状态为 built，并用浏览器／HTTP 确认站点载入。新仓库首次发布可能需要等待；存在 HTTP 缓存时核对最新标题和版本。最终记录 URL、commit、画布尺寸、FPS、采用素材及未完成验收事项。

实现依据：[GitHub Pages API](https://docs.github.com/en/rest/pages/pages)、[Pages 发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。
